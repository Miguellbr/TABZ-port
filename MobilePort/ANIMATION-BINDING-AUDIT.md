# Animation-to-rig audit — prototype findings

Generated by workflow `.github/workflows/animation-binding-audit.yml` on 2026-10-10.

## Results

Both source builds (TABZ Modded v4 and v5.1) produced the same high-level counts:

- 11 Unity asset containers scanned per build
- 33 AnimationClip objects
- 84 SkinnedMeshRenderer objects
- 7 Avatar objects
- 0 container parse errors

Useful named clips include `idle`, `walk`, `run`, `attack`, `fall`, `die`, `gothit`, and `jump`. Several clips contain 124–165 curve bindings. For example, `attack` has 150 bindings and a duration hint around 1.17 seconds. These curves include humanoid-looking transform paths such as `L_FOOT` and nested foot-control transforms.

Candidate skinned meshes found include `construction_worker` (54 bones), `Robot2` (48), `muktar_2` (35), and `RealHumanBean` (11). UnityPy could resolve the mesh pointers and bone counts, but bone names were not exposed reliably in this report; renderer object names are also blank in the serialized records.

## What this tells us

There is enough serialized animation and skinned-mesh data to justify the next step: inspect the full GameObject/component relationships and recover one complete character hierarchy with its Avatar/Animator references. Prefer a candidate whose skeleton paths match the animation curves, then test a minimal idle/walk/attack sequence in Unity.

## Important limits

This is a static audit of the original Windows build's serialized Unity assets. It does **not** mean the model and clips have been imported into the mobile project, and it does not prove that any particular clip plays on any particular rig. No Android APK has been compiled from these recovered assets yet.
